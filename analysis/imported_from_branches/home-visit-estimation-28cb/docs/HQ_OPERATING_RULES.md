# 本部運用ルール（訪問診療・地域推計）

本ドキュメントはわかさクリニックグループ本部向けの**正式運用ルール**です。  
推計エンジン（`home_visit_demand`）の出力解釈と、定例会議での使い方を固定します。

## 1. 指標の定義（変更禁止）

| 指標 | 定義 | 使う | 使わない |
|------|------|------|----------|
| 居宅市場規模 | 指定半径の居宅訪問診療需要（他院含む） | ポテンシャル把握 | 自院目標そのもの |
| 居宅獲得率 | 自院実績居宅 ÷ 居宅市場規模 | 競争力・進捗 | 市場規模の「補正係数」 |
| ユニオン市場 | グループ圏域のメッシュ重複除去後 | グループ全体ポテンシャル | 院別単純合算の合計 |
| 排他的居宅市場 | 当該院が最寄りのメッシュ需要 | 院別KPIの母数（重複圏） | 無視した院間ランキング |
| 施設契約KPI | 契約・担当施設の実績患者 | 施設評価・パネル構成 | 施設市場需要とのシェア |

## 2. 半径ルール（正式）

| 半径 | 位置づけ | 用途 |
|------|----------|------|
| **8 km** | **標準（必須）** | 院間比較、定例レポート、期待獲得率帯 |
| **5 km** | コア（補助） | 立ち上げ初期、強い獲得の再現範囲、営業コア設計 |
| **10 km** | 広域（補助） | 出店・広域需要の確認。獲得率は参考値 |

### 必須ルール

1. 院間比較は**必ず同一半径**（原則 8km）。
2. 短期の居宅目標の母数に **10km市場を使わない**。
3. 重複が大きいクラスターでは、8km市場に加え **排他的居宅市場** を併記する。
4. 半径感度（5/8/10）は四半期に1回以上確認し、標準8kmの妥当性を点検する。

## 3. 期待獲得率帯の使い方

1. 密度帯（高齢者規模）でベース帯を決める。  
2. グループ内近接院・入居系施設密度・**外部在宅寄り競合**で帯を調整する。  
3. 実績獲得率を帯と比較し、判定する。  
   - `above`: 横展開候補  
   - `within`: 様子見（施設偏重なら居宅下限を設定）  
   - `below`: 居宅開拓アクション  

外部競合の主指標は、関東信越厚生局の**在宅療養支援診療所（在支診）**届出受理件数（座標突合済み）です。  
名称近似の在宅クリニック件数は補助指標です。

## 4. アクションシート運用

定例（月次または四半期）で次を確認する。

1. 各院の判定（やる / 様子見 / 横展開 / やらない）  
2. KPIの前月差（獲得率、排他市場比、施設/パネル構成）  
3. 三鷹クラスターの役割分担（重複圏の一次受付ルール）  
4. 浦和は立ち上がり軌跡（3/6/12か月）として別枠（`data/confidential/urawa_ramp.yaml` を毎月更新）  
5. 三鷹クラスターは主担当マップ（`examples/mitaka_cluster_ownership_map.html`）で役割を確認  

出力:

```bash
PYTHONPATH=src python3 scripts/run_hq_pipeline.py
# examples/wakasa_hq_pipeline_report.txt
# examples/wakasa_action_sheets.txt
# examples/wakasa_hq_dashboard.html
```

## 5. 施設の扱い

- 施設は **契約患者数** と **パネル内構成比** で評価する。  
- 施設市場需要は「地域に施設需要があるか」の参考に留め、シェア評価に使わない。  
- パネル施設比率が概ね70%超の院は、居宅新規の下限件数を別途設定する。

## 6. 改訂

- 本ルールの改訂は本部承認後に README / 本ファイルを同時更新する。  
- 期待帯の閾値変更は、実績突合（`compare_actuals.py` / HQパイプライン）を再実行したうえで行う。
